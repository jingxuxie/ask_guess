\begin{abstract}
Language agents in situated environments must decide not only what an instruction might mean, but whether it is useful and safe to act on that interpretation. Existing clarification benchmarks often treat this as static ambiguity detection. We instead frame clarification as a situated value-of-information decision under uncertainty, interaction cost, and task consequences. We introduce \task, a procedural benchmark in which an agent observes a structured scene and instruction, then either acts immediately or asks one clarifying question before acting. Rewards are deterministic and combine task success, clarification cost, and wrong-action cost. Across different models, direct ask-when-needed prompting improves over guessing but remains miscalibrated: it over-asks when ambiguity is harmless and under-asks when wrong actions are costly. An expected communicative utility (\ecu) policy reaches 0.98 utility with no missed or unnecessary clarifications in these main runs. The central lesson is that pragmatic clarification should be evaluated as utility-calibrated interaction, not ambiguity detection alone.
\end{abstract}

\section{Introduction}

A situated language agent often receives instructions that are easy to parse but underspecified for action. A household assistant asked to ``bring the red mug'' may see two red mugs. A file agent asked to ``delete the old draft'' may see two plausible drafts with very different consequences. A robot asked to ``move a spare chair'' may see several chairs, any of which would satisfy the request. In all three cases, the linguistic form of the instruction is ordinary; the difficulty appears only when language is grounded in a particular scene, action space, and set of consequences.

This makes clarification different from ordinary question answering. The agent is not merely deciding whether a sentence has multiple interpretations. It is deciding whether an additional conversational turn is worth its cost. Asking can save the agent from irreversible errors, but it can also waste time, increase user burden, and make an otherwise competent assistant feel brittle. Acting can be efficient, but it can also hide unsafe guessing behind lucky outcomes. A useful situated agent therefore needs a policy for when to ask, not only a detector for whether a query sounds ambiguous.

Our motivating observation is that ambiguity and clarification utility come apart. Ambiguity is sometimes harmless: if any spare folder can be moved, asking which spare folder the user means only pays an unnecessary interaction cost. Ambiguity can also be resolved by context: if one folder is in the user's active workspace and another is stored away, the best action may be clear. Conversely, a high-probability interpretation can still call for clarification if a wrong action is expensive, as in deleting a file or handling a personal object. These cases require the agent to reason jointly about language, scene evidence, outcome equivalence, and risk.

This decision is pragmatic because interpretation depends on context, mutual knowledge, informativeness, and consequences \citep{grice1975logic,sperber1986relevance,clark1986referring,clark1996using,frank2012predicting,goodman2016pragmatic}. It is also situated: the same utterance can require different behavior depending on scene state, affordances, and task stakes \citep{bisk2020experience,min2024situated}. From the decision-making side, clarification resembles a value-of-information problem \citep{rao2018learning,horvitz1999principles}: asking is useful only when the expected improvement in action quality exceeds the cost of interruption. The challenge is to make this idea concrete enough to evaluate modern language agents cheaply and reproducibly.

We introduce \task, a controlled benchmark for this ask-or-act decision. Each episode contains a structured scene, an instruction, candidate user intents with priors, a hidden user intent, and task costs. The agent may act or ask. If it asks, a simulated user answers from the hidden intent and the agent then acts. Because the environment computes rewards automatically, \task supports cheap and reproducible experiments with hosted models and transparent controllers. The benchmark is intentionally narrow: it abstracts away perception and long-horizon planning so that we can isolate the first-turn pragmatic decision of whether communication is worth its cost.

\paragraph{Contributions.}
We introduce a 1,400-episode benchmark for situated clarification; formalize clarification as expected communicative utility (\ecu); compare prompting, private-reasoning prompting, transparent controllers, and an expected-utility wrapper; and analyze why utility calibration helps. The key result is not that language models cannot ask questions. Rather, explicit utility calibration gives a stable rule for when communication is worth its cost, while direct prompting remains sensitive to whether the ambiguity looks like uncertainty, risk, or harmless underspecification.

\section{Clarify-to-Act}

Each \task episode is generated from a compact scene grammar and contains a hidden intent sampled from candidate interpretations. The agent observes the scene and instruction, but not the hidden intent. It outputs either
\[
\{\texttt{type}:\texttt{ACT},\ \texttt{action}:a,\ \texttt{target\_id}:o\}
\]
or
\[
\{\texttt{type}:\texttt{ASK},\ \texttt{question}:q\}.
\]
If it asks, the simulated user returns a state, location, or ownership answer associated with the hidden target, and the agent then chooses a final action. Episodes are capped at one question to focus evaluation on the first-turn ask-or-act decision.

The canonical dataset contains 1,400 episodes. Splits are balanced across the five categories in Table~\ref{tab:benchmark-categories}; the overall oracle ask rate is 0.50.

\paragraph{Reward and oracle.}
The reward is
\[
R=\mathbb{1}[\mathrm{success}]-C_{ask}\mathbb{1}[\mathrm{asked}]-C_{wrong}\mathbb{1}[\mathrm{wrong}].
\]
Success is defined by matching the hidden intent's success-equivalence class, not necessarily by matching a target identity. Let $p_{\max}$ be the prior mass of the best success-equivalence class. Acting has expected utility $EU(act)=p_{\max}-(1-p_{\max})C_{wrong}$, while asking has $EU(ask)=1-C_{ask}$. The oracle asks when $EU(ask)>EU(act)+\epsilon$. We report net utility, success, ask rate, missed clarification, and unnecessary clarification.

\paragraph{Simulated user and leakage controls.}
The simulated user is deterministic, which makes replay exact. Hidden owner names are redacted from prompts, hidden-owner objects receive neutral state labels, and target identifiers are neutral. A simulated-user audit verifies that deterministic answers resolve the hidden success class in all generated oracle-ask cases and all actual asked rows.

\section{Methods and Experiments}

We compare four families of policies. \directact\ never asks. \textsc{AskAlways} and \textsc{RawAmbiguity} ask whenever ambiguity is present, measuring over-clarification. \askneeded\ prompts the model to ask only when acting could plausibly fail; a private-reasoning variant encourages hidden deliberation before the final JSON answer. The \ecu\ policy first asks the model to propose candidate interpretations, probabilities, context-resolution flags, equivalence flags, and risk estimates. Deterministic code then groups candidates into success-equivalence classes and computes $EU(ask)-EU(act)$. If the margin exceeds 0.1, the model generates a clarifying question; otherwise the agent acts. Model-declared equivalence is accepted only when supported by explicit cues such as ``spare,'' ``any,'' or ``one of.''

We also test paraphrased instructions, terser answer styles, reversed object order, compact natural-language scene descriptions, held-out ambiguity mixes, component ablations, candidate-probability diagnostics, and cost re-scoring.

\section{Results}

We emphasize three takeaways.

\subsection{Takeaway 1: utility calibration improves ask-or-act behavior}

Table~\ref{tab:headline-api} summarizes the main results. On GPT-5-mini, direct \askneeded\ prompting improves over never asking but misses more than half of the oracle clarification cases. \ecu\ reaches 0.98 utility with full task success and no ask errors. Stronger models narrow the gap. GPT-5.4-mini prompts over-clarify many oracle-act cases, while GPT-5.5 plain prompting under-clarifies risk-sensitive cases. \ecu\ keeps the ask rate aligned with the oracle and has zero missed and zero unnecessary clarifications in the main current-model runs.

\subsection{Takeaway 2: ambiguity and uncertainty are not enough}

All canonical test episodes have multiple candidate interpretations, yet half are oracle-act cases and half are oracle-ask cases. A raw ambiguity detector asks on everything and pays unnecessary clarification cost whenever context or outcome equivalence already resolves the instruction. An uncertainty-only controller improves over raw ambiguity but still misses value-relevant structure: equivalent outcomes make entropy harmless, while high wrong-action cost can make clarification valuable despite a high top prior.

\subsection{Takeaway 3: \ecu\ separates interpretation from decision-making}

\ecu\ works by separating semantic interpretation from the ask decision. The LLM proposes plausible interpretations and rough probabilities; deterministic code computes whether asking is worth the cost. Ablations support this mechanism. If every model-declared equivalence flag is trusted, utility drops because the model sometimes collapses distinct referents. If equivalence is never collapsed, success remains high but the agent asks many unnecessary questions. The conservative equivalence guard is therefore essential.

Candidate-probability diagnostics also support a bounded mechanism claim: \ecu\ does not require perfect hidden-intent prediction; it needs candidate sets and rough relative probabilities good enough for the utility margin to track the oracle margin.

\section{Qualitative Analysis}

The most informative failures are first-turn calibration failures: cases where the model either acts when information would have high value, or asks when the scene already makes action safe. These errors are qualitatively different from second-turn grounding errors. In our main runs, when a baseline asks an appropriate question, it usually uses the simulated answer successfully. The hard part is deciding whether to ask in the first place.

Two patterns recur across the baseline failures. First, direct prompting often behaves as if uncertainty alone were the relevant signal. It asks for clarification in equivalent-outcome cases because there are several candidate objects, even though all candidates lead to the same reward. This is a pragmatic failure rather than a semantic one: the model recognizes that the referent is underspecified, but does not recognize that the underspecification is harmless. Second, direct prompting can be too willing to act in high-stakes cases. In risk-sensitive delete-file episodes, one interpretation often has a high prior, but the remaining uncertainty is still worth resolving because the wrong-action cost is large.

The preference/social category exposes a more subtle issue. Instructions such as ``put my mug away'' require the agent to know whether ownership is visible in the scene. If ownership is visible and matches the current user, asking is unnecessary. If ownership is hidden, acting requires guessing which object is the user's. This category is important because it connects clarification to social and indexical reasoning: the agent must not only parse the word ``my,'' but also decide whether the scene provides enough evidence to ground it.

The qualitative examples also clarify what \ecu\ is not doing. It is not simply asking more often: its ask rate is close to the oracle and lower than ambiguity-only policies. It is not solving the task by making the simulated user easier: the same deterministic answer mechanism is available to all policies once they ask. The improvement comes from separating the interpretation step from the decision step. The model proposes possible meanings; the utility rule decides whether information changes the optimal action.

This separation is useful even when the model is strong. Larger models and private reasoning reduce some obvious failures, but the remaining errors are still structured: over-asking when ambiguity is harmless, under-asking when risk is high, and misusing context in preference/social cases. These are exactly the cases targeted by success-equivalence grouping, wrong-action costs, and conservative context/equivalence guards. The qualitative evidence therefore supports the paper's main claim: clarification should be evaluated as a calibrated interaction policy, not as a generic willingness to ask questions.

\section{Related Work}

\paragraph{Clarification and ambiguity.}
Clarification has been studied in question answering, conversational search, task-oriented dialogue, and language-agent settings. AmbigQA, CLAM, and CLAMBER focus on ambiguous information needs and whether systems should ask questions before answering \citep{min2020ambigqa,kuhn2022clam,zhang2024clamber}. Recent language-agent work similarly studies whether agents can identify missing user intent and elicit additional information before acting \citep{qian2024tell}. These benchmarks motivate the need for clarification, but they often evaluate ambiguity at the query level. \task instead grounds the decision in a scene and reward function: the same ambiguous instruction may be oracle-act or oracle-ask depending on context, equivalence, and risk.

\paragraph{Value of information and mixed initiative.}
Our formulation is closest in spirit to value-of-information views of clarification. Rao and Daum{\'e} rank questions by expected value of perfect information, while mixed-initiative systems study when a system should interrupt or take initiative \citep{rao2018learning,horvitz1999principles}. Work on grounded human-robot dialogue and interactive word learning likewise shows that asking questions can improve learning or task execution, but that interaction imposes cost on the human partner \citep{thomason2019improving,yu2017learning}. We adopt this perspective but make the ask-or-act decision deterministic and automatically scorable, which lets us separate the utility of asking from the language quality of the question.

\paragraph{Situated and embodied instruction following.}
Situated language understanding has a long history, from blocks-world command following to modern household and robotic environments \citep{winograd1972understanding,tellex2011understanding,shridhar2020alfred,padmakumar2022teach,ahn2022saycan}. Recent situated-instruction work emphasizes that natural instructions are often incomplete because speakers rely on shared context, ongoing activity, and visible affordances \citep{bisk2020experience,min2024situated}. \task complements these environments by removing perception and long-horizon planning in order to isolate one pragmatic decision: whether the agent should request information before acting.

\paragraph{Pragmatics, reference, and communicative utility.}
Classic pragmatics treats communication as cooperative, context-sensitive action rather than literal decoding \citep{grice1975logic,sperber1986relevance,clark1986referring,clark1996using}. Work on referring expression generation and Rational Speech Act models formalizes similar ideas as inference about speakers, listeners, distractors, and utilities \citep{dale1995computational,frank2012predicting,goodman2016pragmatic,monroe2017colors,golland2010game}. Our benchmark adapts this view to the agent side of the interaction: the agent must decide whether the user's utterance is informative enough for action, given the expected cost of acting incorrectly.

\paragraph{Interactive and social language agents.}
Emergent-communication, visual-dialogue, collaborative drawing, and social-agent benchmarks study communication as goal-directed interaction rather than isolated text prediction \citep{lazaridou2017multi,devries2017guesswhat,kim2019codraw,zhou2024sotopia}. These settings are broader and more realistic, but often require complex simulation or evaluator judgments. \task is narrower but more controlled: the environment computes success and clarification utility directly. This makes it useful as a low-cost diagnostic for whether multi-turn language agents know when communication itself is useful.

\section{Limitations}

\task\ is synthetic and text/JSON-based. It isolates ambiguity, context, equivalence, ask cost, and wrong-action cost, but does not test perception, long-horizon planning, multimodal grounding, or real human interaction. The simulated user answers deterministically; audits verify that these answers resolve the hidden success class, but this is not a human-response study. Finally, real systems would need to estimate priors and costs from user preferences, domain risk, and environment state.

\section{Conclusion}

Clarification is not merely a response to ambiguity. It is a situated decision about whether information is worth the cost of asking for it. \task\ provides a controlled benchmark for this decision. Across offline diagnostics and evaluations, expected communicative utility improves ask-or-act behavior by asking when clarification changes the expected outcome and acting when it does not. Pragmatic clarification should therefore be evaluated as utility-calibrated interaction policy rather than static ambiguity detection alone.
